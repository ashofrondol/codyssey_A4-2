## 프로젝트 개요

앞선 미션(A4-1)에서는 TF-IDF와 코사인 유사도로 문서를 검색하고 분류하는 **통계 기반** 방법을 썼다. 통계 기반 방법은 많은 데이터에서 일반적인 패턴을 잡는 데 강하지만, "이메일 주소를 뽑아라"처럼 정해진 형식의 정보를 정확히 꺼내는 일에는 맞지 않는다. 이 미션은 정보 추출(Information Extraction, 정리되지 않은 글에서 정해진 형태의 정보를 뽑아내는 기술)을 **규칙 기반(Rule-based, 사람이 직접 규칙을 적는 방식)** 으로 해 본다. 도구는 두 가지다. 정규표현식(Regular Expression, 글자 패턴을 찾는 문법)으로 연락처·날짜·금액 같은 정보를 뽑고, 감성 사전(Sentiment Lexicon, 단어마다 긍정/부정 점수를 적어 둔 사전)으로 글의 기분을 판단한다. 실무 시나리오는 고객 문의 글에서 핵심 정보를 뽑고 그 문의가 불만인지 만족인지 판단하는 통합 파이프라인이다. 핵심 질문은 "규칙으로 언어를 정의할 수 있는가?"이며, 규칙 기반의 장점(높은 정밀도, 해석 가능성)과 한계(낮은 확장성, 유지보수 어려움)를 체감한다.

**핵심 과제** (명세의 "기능 요구 사항")

1. 정규표현식으로 이메일, 전화번호, 날짜, 금액, URL 5가지 패턴을 추출하고 정규화한다.
2. 감성 사전(200개 이상 단어)으로 문장의 감성 점수를 계산하고 부정어·강조어를 처리한다.
3. 정보 추출(정밀도·재현율)과 감성 분석(정확도·F1)을 평가하고 실패 사례를 분석한다.

### 먼저 확인할 것: 정보 추출 데이터는 직접 만든다

명세는 정보 추출 테스트 데이터를 "직접 생성하는 것이 효과적"이라고 하고, 평가 기준도 "직접 작성한 테스트 문장"이다. 그래서 정보 추출 쪽은 공개 데이터셋을 찾지 않는다. 직접 만들 때는 다음을 지킨다.

- **진짜 연락처를 쓰지 않는다.** 이메일과 URL은 예시용으로 예약된 도메인 `example.com`, `example.net`, `example.org`([RFC 2606](https://www.rfc-editor.org/rfc/rfc2606))를 쓴다. 전화번호는 지어낸 번호를 쓰고, 인터넷에서 본 실제 번호를 옮기지 않는다.
- **문장마다 정답을 함께 적는다.** 예: `{"text": "...", "email": ["user@example.com"], "date": ["2024-03-15"]}`. 정답(뽑혀야 할 값)이 있어야 정밀도와 재현율을 계산할 수 있다.
- **일부러 어려운 문장도 넣는다.** 명세의 실패 예시("공일공-일이삼사-오육칠팔"), 패턴이 없는 문장, 비슷하지만 정답이 아닌 문장(예: 버전 번호 `1.2.3`)을 섞으면 실패 사례 5건을 찾기 쉽다.

### 추천: NSMC (레이블 데이터) + KNU 한국어 감성사전 (사전)

| 역할 | 데이터 | 라이선스 | 규모 |
|---|---|---|---|
| 감성 레이블 데이터 | [NSMC (네이버 영화 리뷰)](https://github.com/e9t/nsmc) | CC0 1.0 (확인, 저장소 README의 라이선스 표시) | 20만 건, 긍정·부정 각 10만 건. 필드 `id`, `document`, `label`(0 = 부정, 1 = 긍정), 탭 구분 |
| 감성 사전 | [KNU 한국어 감성사전 (KnuSentiLex)](https://github.com/park1200656/KnuSentiLex) | 라이선스 표시 없음 (확인: 저장소에 LICENSE 파일이 없고 README에도 이용 조건이 없다) | README 기준 14,843개 항목. `data/SentiWord_info.json`의 각 항목은 `word`, `word_root`, `polarity` |

| 요구사항 | 해결 방법 |
|---|---|
| 레이블 데이터 100개 이상 | NSMC에서 `random_state`를 고정해 긍정·부정을 같은 수로 뽑는다(예: 각 100개). A4-1에서 NSMC를 썼다면 그 데이터를 재활용한다 |
| 감성 사전 200개 이상 | KNU 사전만으로 충분하다. `polarity` 값은 문자열이며(파일 앞부분에서 본 값은 -2 ~ 2), 숫자로 바꿔 쓴다 |
| 도메인 특화 단어 30개 | 도메인은 "영화 리뷰"다. KNU 사전에 없는 영화 관련 표현(예: 명작, 졸작, 몰입감, 연기력, 노잼, 꿀잼, 재관람)을 직접 점수를 매겨 추가하고, 추가한 목록을 따로 파일로 둔다 |
| 외부 사전 출처 명시 | README에 KNU 사전의 저장소 주소와 만든 곳(군산대학교 Data Intelligence Lab)을 적는다 |
| 오분류 사례 10건 | 영화 리뷰에는 반어("참 잘 만들었네요 ㅋ"), 줄임말, 맞춤법이 틀린 표현이 많아 실패 사례를 모으기 쉽다 |
| 보너스 2 (10, 100, 1000개) | NSMC는 20만 건이라 1,000개도 넉넉하다 |

**약점**: KNU 사전은 국어사전 뜻풀이 등을 바탕으로 만든 일반 사전이라, "노잼" 같은 인터넷 말투가 잘 잡히지 않을 수 있다. 바로 이 부분을 도메인 특화 단어로 채운다. 또 NSMC는 원래 별점 1~4점을 부정, 9~10점을 긍정으로 나눈 데이터라 중립 리뷰가 없다.

### 데이터를 다룰 때 주의할 점

- **내려받은 원본은 레포에 올리지 않는다.** NSMC 전체 파일과 KNU 사전 원본은 `data/raw/`에 두고 `.gitignore`로 제외한다. 특히 KNU 사전은 라이선스가 표시되어 있지 않으므로 다시 배포하지 않는다. 직접 만든 테스트 문장, 직접 추가한 도메인 단어, NSMC에서 뽑은 평가용 샘플(CC0)은 레포에 올려도 된다.
- **명세의 KNU 로드 예시 수정**: 명세 예시는 `pd.read_csv('SentiWord_info.json')`인데, 이 파일은 JSON 배열이라 CSV로 읽을 수 없다. `json.load()`나 `pd.read_json()`으로 읽어야 한다. 파일 위치도 저장소의 `data/` 폴더 안이다.
- **NSMC는 탭 구분이다.** `pd.read_csv(..., sep='\t')`로 읽고, 리뷰 본문이 빈 행이 있을 수 있으니 결측치를 지운다.
- **출처 표기**: README의 데이터 구성 절에 NSMC(CC0 1.0)와 KNU 한국어 감성사전(저장소 주소, 만든 곳)을 적는다. 제약 사항이 외부 사전의 출처 명시를 요구한다.

### 1. 정규표현식 기반 정보 추출

글자 패턴 규칙으로 글 속의 연락처·날짜·금액 등을 찾아내고, 같은 정보가 여러 모양으로 적혀 있어도 하나의 통일된 형식(정규화)으로 바꿔 돌려준다.

- [ ] 이메일 주소 추출 함수 (예: `user@domain.com`, `user.name@sub.domain.co.kr`)
- [ ] 전화번호 추출 함수 (예: `010-1234-5678`, `02-123-4567`, `031-1234-5678`)
- [ ] 날짜 추출 함수 (예: `2024년 1월 15일`, `2024/01/15`, `2024-01-15`)
- [ ] 금액 추출 함수 (예: `10,000원`, `1억 2천만원`, `$100`)
- [ ] URL 추출 함수 (예: `https://www.example.com/path?query=value`)
- [ ] 각 패턴에 대해 최소 3가지 이상의 변형을 처리한다.
- [ ] 추출 결과를 정규화된 형식으로 반환한다. (예: 날짜는 ISO 8601 형식, 금액은 정수 값, 전화번호는 하이픈 구분 통일 형식 등)
- [ ] 모든 정규표현식 패턴에 의도와 매칭 범위를 설명하는 주석을 단다.

### 2. 감성 사전 및 감성 분석

단어마다 매겨 둔 점수를 더해 문장의 기분을 판단한다. 부정어("않다", "없다")는 점수의 부호를 뒤집고, 강조어("매우", "정말")는 점수를 크게 만든다.

- [ ] 공개 감성 사전을 활용하거나 직접 구축한다. (최소 200개 이상 단어)
- [ ] 외부 사전을 쓰면 출처를 명시하고 도메인 특화 단어를 최소 30개 이상 직접 추가한다.
- [ ] 문장의 감성 점수를 계산하는 함수를 구현한다.
- [ ] 부정어 처리를 구현한다. (예: "좋지 않다" → 부정)
- [ ] 강조어 처리를 구현한다. (예: "매우 좋다" → 강한 긍정)
- [ ] 최소 요구(필수) 범위를 모두 구현한다: 토큰화 + 감성사전 점수 합산 + 부정어 반전 + 강조어 가중치 + 이중 부정 단일 패턴 처리

> 반어/비꼼, 복합 감성(Aspect), 문맥 의존 표현 등은 도전 범위(선택)로, 보너스 과제로 분류된다.

### 3. 시스템 평가

정밀도(Precision)는 "뽑아낸 것 중 맞은 비율", 재현율(Recall)은 "뽑아야 할 것 중 실제로 뽑은 비율"이다. 규칙이 얼마나 정확하고 얼마나 빠짐없이 동작하는지 숫자로 확인한다.

**정보 추출 평가**

- [ ] 직접 작성한 테스트 문장 50개 이상(패턴별 10문장 이상)으로 테스트 세트를 구성한다.
- [ ] 패턴별 정밀도(Precision)와 재현율(Recall)을 계산한다.
- [ ] 실패 사례 5건 이상을 유형별로 분류하고 원인을 분석한다.

**감성 분석 평가**

- [ ] 레이블 데이터 100개 이상으로 정확도(Accuracy) 및 F1 점수를 산출한다.
- [ ] 부정어/강조어 규칙 적용 전후 성능을 비교한다.
- [ ] 오분류 사례 10건 이상을 수집하고 원인을 분석한다.

## 결과 예시 (명세 참고)

명세는 "정답이 아니라 참고 예시이며, 레포지토리 구조는 달라도 된다"고 밝힌다. 예시는 다음을 보여 준다.

- **정보 추출 결과**: 문의 문장 하나에서 이메일, 전화, 날짜(`2024-03-15`로 정규화), 금액(`50000`으로 정규화)을 뽑아 보여 준다.
- **감성 분석 과정**: 토큰화 → 감성 단어 탐지 → 부정어 탐지(감성 반전) → 강조어 탐지(강도 ×1.5) → 계산 → 최종 판정 순서로 보여 준다.
- **규칙 실패 사례**: 한글 숫자 표기 전화번호("공일공-일이삼사-오육칠팔") 미지원, 복합 감성을 단일 점수로 표현 불가 사례를 든다.

감성 분석 과정 형식 예시:

```
=== 감성 분석 과정 ===
문장: "이 식당은 정말 맛있지 않았어요"
1. 토큰화: [이, 식당, 은, 정말, 맛있, 지, 않았어요]
2. 감성 단어 탐지: 맛있(+2)
3. 부정어 탐지: '않았어요' → 감성 반전
4. 강조어 탐지: '정말' → 강도 ×1.5
계산: (+2) × (-1) × 1.5 = -3
최종 판정: 부정
```

## 명세에서 확인할 점

- **도메인 특화 단어 30개의 조건**: 7. 제약 사항은 "외부 사전 사용 시 출처를 명시하고, 도메인 특화 단어 최소 30개 이상을 직접 추가한다"로 외부 사전을 쓸 때의 조건처럼 적었지만, 데이터 준비 체크리스트는 조건 없이 "도메인 특화 단어 30개 이상 추가"라고 적었다. 사전을 직접 구축할 때도 필요한지 확인이 필요하다.
- **달러 금액의 정규화**: 금액은 "정수 값"으로 정규화하라고 하면서 예시에 `$100`이 있다. 원화와 달러를 같은 정수로 표현할 때 통화 단위를 어떻게 구분할지(예: 통화 정보를 함께 반환할지)는 적혀 있지 않다.
